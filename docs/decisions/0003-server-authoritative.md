# ADR 0003 — 서버 권위(Authoritative) 멀티플레이어 모델

- **상태**: Accepted
- **작성일**: 2026-05-16

## 배경

게더타운형 2D 멀티플레이어. 40명 동시접속. 위치·점수·퀴즈 매칭 등 게임 상태의 신뢰성과 일관성이 중요.

클라이언트 권위 모델(클라가 위치를 계산해 서버에 보고)은 단순하지만:
- 치팅 가능 (클라가 마음대로 위치 보고)
- 일관성 깨짐 (네트워크 지연으로 서로 다른 클라가 다른 상태 봄)
- 동시 접근(퀴즈 페어 매칭) 경합 해결 어려움

## 결정

**서버 권위(authoritative) 모델** 채택.

### 핵심 원칙
1. **클라는 입력 인텐트만**: `player:input { dir }` 같은 의도만 보내고, 실제 위치 갱신은 서버가
2. **서버 tick 루프**: 20Hz(50ms)로 입력 처리·충돌·AOI 계산·브로드캐스트
3. **클라는 보간(interpolation)**: 수신한 위치를 기준으로 부드러운 렌더
4. **퀴즈 페어 매칭은 락 획득**: 서버가 페어 락을 잡아 양쪽에 동시 송신, 중복 매칭 방지

## 대안과 트레이드오프

### 클라 권위
- ✅ 서버 구현 단순, 응답성 좋음
- ❌ 치팅, 일관성, 매칭 경합 등 문제 다수
- ❌ 40명 규모에 이미 부적합

### 결정론적 lockstep (격투/RTS류)
- 모든 클라가 같은 시뮬레이션 실행, 입력만 동기화
- ❌ 게더타운류엔 과한 복잡도

### 부분 권위 (위치는 클라, 점수만 서버)
- 위치 치팅은 허용하지만 점수만 신뢰
- 본 게임은 위치 자체가 게임플레이(퀴즈 트리거)에 영향 → 위치도 권위 필요

## 결과

### 장점
- 일관성 보장
- 치팅 차단 (클라가 위치 보고해도 서버 무시)
- 퀴즈 매칭 race condition 자연스럽게 해결 (서버에서 페어 락)

### 부담
- 서버 부하 (tick 처리). 40명엔 무시 가능 수준 (CPU 1~3%)
- 클라 응답성: 입력 → 서버 처리 → 브로드캐스트까지 50~100ms 지연. **클라 측 클라이언트 예측(client prediction)**으로 보완 가능하지만 본 MVP에선 단순 보간만으로 충분
